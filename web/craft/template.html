ExpertCraft

Train a language model with up to 70 billion parameters on your own phone. A small model stays in RAM. The other parameters live in millions of page-sized experts in a file on flash, and each word reads, trains and rewrites only a handful of them. No GPU, no account, no cloud.

Or just tell your AI

Install the Expert Craft skill from github.com/Tharunmaks/Stream- (folder craft/skills/expert-craft), then use it to plan and train a 70B model on this phone and explain every step to me.
1

Small model in RAM

An ordinary transformer of a few million parameters, trained the normal way with hand-written, gradient-checked backpropagation.

2

Experts on flash

Each expert is a tiny network that fills exactly one 4 KB flash page. About 18 million of them make 70 billion parameters. The file is sparse, so unused experts take no space.

3

Routing by hash

The last 1, 2 and 3 tokens each pick one expert by hash, so the same context always reaches the same page and every occurrence trains it (hashed n-gram memory, as in Engram and the Byte Latent Transformer). A learned product-key router is available with --route pk.

4

Train in place

Only those 3 pages are read, updated (row-wise Adagrad, 8-bit stochastic rounding) and written back by native kernels your device compiles for itself. The work per word is that of the small model.

Start

Train it on your phone

Termux (from F-Droid) on Android, or any Linux/Mac/Windows shell with Python 3. Only NumPy is needed. Keep the phone on a charger and use internal storage (an SD card or FAT volume cannot hold a sparse file).

pkg install -y python python-numpy git
git clone https://github.com/Tharunmaks/Stream-.git ~/Stream-
cd ~/Stream-

# 1. see what 70B means on THIS phone (measures speed, storage and wear, then explains it)
python3 craft/expertcraft.py phone-plan 70e9 --minutes 600

# 2. train: any text file or folder, or the free TinyStories sample
python3 craft/expertcraft.py phone-train mymodel --dataset tinystories --params 70e9 --minutes 600 --min-battery 25 --max-temp 42 --max-wear-gb 2000

# 3. stop any time (Ctrl-C saves); run the same command again to continue

# 4. talk to it
python3 craft/expertcraft.py phone-sample mymodel --prompt "Once upon a time"
python3 craft/expertcraft.py phone-status mymodel

Projects live in ~/expertcraft (set EXPERTCRAFT_HOME to change it). The tool never writes outside that folder.

Straight answer

What 70 billion parameters on a phone really means

  • True: all 70 billion parameters exist on the phone, are read, trained and saved there, for free, without a GPU or network. Training a dense 70B model this way is impossible: it costs about 4×10^20 FLOPs per billion tokens, hundreds of years at the speed of a phone CPU. That is why the model is sparse.
  • Also true: each word uses only about 0.005% of them, and a phone processes a few tens of millions of tokens a day. The text quality follows the words seen and the small dense model, not the file size. Expect small-model text, a little better than the same small model without experts (measured below).
  • Cost: every word reads and rewrites 3 flash pages (12 KB). Nonstop training therefore writes terabytes per day; the planner shows it and --max-wear-gb caps it. Use a charger and keep the phone cool.
  • Not done: there is no GPU path for the experts and no export to the fast C engine yet; a trained model is used with phone-sample (NumPy). It was tested on a 4-core Linux PC, not yet on a phone, so measure with phone-plan first.

CommandWhat it does

      
        
phone-plan SIZEMeasures this device and prints the plan: parameters, speed, uses per expert, flash written, honest summary.

        
phone-train NAMEPrepares data and tokenizer, trains, saves, resumes. Guards: --min-battery, --max-temp, --max-wear-gb, --minutes.

        
phone-sample NAMEGenerates text from the trained model.

        
phone-status NAMELoss trend, experts created, flash written, disk used.

        
plan / design / scaffoldFree GPU planning and a ready-to-train PyTorch project with Colab and Kaggle notebooks.

        
run / status / stopRun the scaffolded project's data, train, export and sample steps in the background.
